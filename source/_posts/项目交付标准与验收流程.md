## 适用场景

项目做完了，客户不断挑毛病不给验收，或者不知道该交付什么东西。需要明确交付标准和验收流程，让项目顺利收尾。

## 实现原理

交付和验收是项目的最后一步，也是最容易出纠纷的环节。通过明确交付物清单、验收标准、验收期限，可以避免客户无限期挑毛病，保证项目顺利收尾拿到尾款。

## 具体步骤

### 第一步：交付物清单

根据客户需求，交付物可能包括：

**1. 数据类**
- 数据文件（CSV/Excel/JSON）
- 数据说明文档（字段含义、数据量、采集时间）
- 数据质量报告（完整率、重复率）

**2. 代码类**
- 爬虫源代码（.py文件）
- 依赖清单（requirements.txt）
- 使用说明文档
- 配置文件（config.py）
- 日志文件

**3. 服务类**
- 部署好的爬虫服务
- 管理后台/可视化界面
- API接口文档
- 服务器配置说明

**4. 文档类**
- 项目说明文档
- 使用教程
- 维护说明
- 常见问题FAQ

### 第二步：交付前自检

交付前一定要自己先测试：

**1. 功能测试**
- [ ] 爬虫能正常运行
- [ ] 能采集到目标数据
- [ ] 数据字段完整
- [ ] 翻页正常
- [ ] 异常处理正常

**2. 数据质量检查**
- [ ] 数据量符合要求
- [ ] 没有大量重复
- [ ] 字段没有大面积缺失
- [ ] 数据格式正确
- [ ] 抽样验证数据真实性

**3. 代码检查**
- [ ] 代码能在干净环境运行
- [ ] 依赖都在requirements.txt里
- [ ] 配置项都抽出来了
- [ ] 有基本的错误处理
- [ ] 没有硬编码的敏感信息

**4. 文档检查**
- [ ] 使用说明写清楚了
- [ ] 环境配置步骤明确
- [ ] 常见问题有说明
- [ ] 联系方式留下了

### 第三步：交付流程

**推荐流程：**

1. **内部测试通过**
   - 自己跑一遍，确认没问题
   - 准备好交付物

2. **发送演示**
   - 发截图/录屏给客户看效果
   - 发部分样本数据（如前100条）
   - 不要一次性给完整代码/全量数据

3. **客户确认**
   - 客户确认效果符合需求
   - 有问题及时修改
   - 客户书面确认"没问题"

4. **收取尾款**
   - 提醒客户付尾款
   - 确认尾款到账

5. **正式交付**
   - 尾款到账后，发完整交付物
   - 发送使用说明
   - 告知维护期和联系方式

6. **售后跟进**
   - 交付后1-3天跟进使用情况
   - 及时解决使用问题
   - 维护期内免费调整

### 第四步：验收标准

**一定要在交付前和客户约定验收标准：**

**1. 功能验收**
- 能正常运行，不报错
- 能采集到约定的字段
- 数据量达到约定数量
- 运行速度在合理范围

**2. 数据验收**
- 数据完整率≥95%（或约定的比例）
- 重复率≤5%
- 字段缺失率≤约定值
- 抽样检查数据真实

**3. 验收期限**
- 交付后3天内验收
- 超过3天不反馈视为验收通过
- 验收期内提出的问题免费修改
- 验收期后新需求另行收费

**4. 验收方式**
- 客户自行测试
- 远程演示
- 提供测试账号

### 第五步：应对客户挑毛病

**客户说"数据有缺失"：**
> "您说一下具体是哪些字段缺失，缺失比例多少？我看一下是网站本身的问题还是爬虫的问题。如果是爬虫的问题我马上修，如果是网站本身没有这个数据，那确实爬不到。"

**客户说"速度太慢"：**
> "当前速度是XX条/秒，因为网站有频率限制，太快会被封IP。如果需要更快，可以加代理IP，不过代理费用需要您这边出，大概XX元/月。"

**客户说"我要加个功能"：**
> "这个功能之前需求里没有提到，属于新增需求。我评估一下，大概需要X天，费用XX元。您看需要加吗？"

**客户说"再帮我改改"（验收期后）：**
> "这个已经超出免费维护范围了，不过小问题我可以帮您调一下。如果是大的改动，需要另行收费，我给您报个价？"

### 第六步：交付文档模板

```markdown
# 项目交付文档

## 项目信息
- 项目名称：
- 客户：
- 交付日期：
- 维护期：至XXXX年XX月XX日

## 交付物清单
1. 爬虫源代码（src/目录）
2. 数据文件（data/目录）
3. 使用说明（README.md）
4. 依赖清单（requirements.txt）
5. 配置文件（config.py）

## 使用说明
### 环境要求
- Python 3.8+
- 依赖安装：pip install -r requirements.txt

### 运行方式
1. 修改config.py中的配置
2. 运行：python main.py
3. 数据保存在data/目录

### 配置说明
- target_url：目标网站
- page_count：采集页数
- delay：请求间隔（秒）

## 数据说明
- 数据量：XX条
- 字段：XX、XX、XX
- 采集时间：XXXX年XX月XX日
- 完整率：约XX%

## 维护说明
- 维护期：XXXX年XX月XX日前
- 维护内容：bug修复、网站小改版调整
- 超出维护期：按次收费，XX元/次
- 联系方式：微信/QQ/电话

## 常见问题
Q: 运行报错怎么办？
A: 先看logs/目录下的日志文件，把错误信息发给我

Q: 网站改版了怎么办？
A: 维护期内免费调整，维护期后收费调整
```

## 完整代码

```python
# 交付前的自检脚本示例
import os
import subprocess
import sys

def check_dependencies():
    """检查依赖是否都在requirements.txt里"""
    # 导入项目所有模块，检查依赖
    print("检查依赖...")
    result = subprocess.run([sys.executable, "-m", "pip", "freeze"], capture_output=True, text=True)
    print("已安装包数量:", len(result.stdout.strip().split('\n')))

def test_spider():
    """测试爬虫能否运行"""
    print("测试爬虫...")
    try:
        # 运行爬虫，限制只爬几页
        result = subprocess.run(
            [sys.executable, "main.py", "--test"],
            capture_output=True,
            text=True,
            timeout=60
        )
        if result.returncode == 0:
            print("测试通过")
            return True
        else:
            print("测试失败:", result.stderr)
            return False
    except Exception as e:
        print("测试异常:", e)
        return False

def check_data_quality(file_path):
    """检查数据质量"""
    import pandas as pd
    df = pd.read_csv(file_path)
    print(f"数据量: {len(df)} 条")
    print(f"字段数: {len(df.columns)} 个")
    print(f"重复率: {df.duplicated().mean()*100:.1f}%")
    print(f"缺失率:")
    print(df.isnull().mean() * 100)

def package_project():
    """打包项目"""
    import zipfile
    files = []
    for root, dirs, filenames in os.walk("."):
        for f in filenames:
            if not f.startswith(".") and "__pycache__" not in root:
                files.append(os.path.join(root, f))
    
    with zipfile.ZipFile("交付包.zip", "w", zipfile.ZIP_DEFLATED) as zf:
        for file in files:
            zf.write(file)
    print(f"打包完成，共{len(files)}个文件")

if __name__ == "__main__":
    print("=== 交付前自检 ===")
    check_dependencies()
    if test_spider():
        check_data_quality("data/result.csv")
        package_project()
        print("=== 自检完成，可以交付 ===")
    else:
        print("=== 自检失败，请修复后再交付 ===")
```

## 注意事项

1. **先验收再给钱** — 客户确认验收后再要尾款，不要反过来
2. **验收期限要明确** — 不要让客户无限期验收，约定3-7天
3. **交付物要齐全** — 代码、文档、数据都要给，不要缺东西
4. **自己先测试** — 交付前一定要自己跑一遍，不要把bug交给客户
5. **留好交付证据** — 交付记录、客户确认都要保存
