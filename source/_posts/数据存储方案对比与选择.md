## 适用场景

爬取的数据不知道该存哪里，CSV、Excel、MySQL、MongoDB各有什么优缺点。需要根据数据量和使用场景选择合适的存储方案。

## 实现原理

爬虫数据存储有多种方案，从简单的文件到复杂的分布式数据库，各有适用场景。选择存储方案主要考虑：数据量、数据结构、查询需求、并发写入、成本和维护难度。

## 具体步骤

### 第一步：CSV/Excel（文件存储）

**CSV特点：**
- 纯文本格式，通用性强
- 任何软件都能打开
- 写入简单，不需要额外依赖
- 适合小数据量（<10万条）

**Excel特点：**
- 有格式，可读性好
- 可以直接用Excel打开编辑
- 单表最多104万行
- 适合交付给非技术人员

**优点：**
- 零配置，开箱即用
- 文件方便传输和分享
- 不需要数据库服务
- 客户容易接受

**缺点：**
- 不支持复杂查询
- 不支持并发写入
- 大数据量性能差
- 不适合长期存储

**适用场景：**
- 小数据量（<10万条）
- 一次性采集
- 交付给客户
- 简单数据分析

**代码示例：**
```python
import csv

# 写入CSV
with open('data.csv', 'w', newline='', encoding='utf-8') as f:
    writer = csv.DictWriter(f, fieldnames=['title', 'price', 'url'])
    writer.writeheader()
    writer.writerow({'title': '商品1', 'price': '99', 'url': 'https://...'})

# 读取CSV
with open('data.csv', 'r', encoding='utf-8') as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row['title'])
```

### 第二步：JSON文件

**特点：**
- 支持嵌套结构
- 适合非结构化数据
- Python原生支持
- 可读性好

**优点：**
- 支持复杂数据结构
- 不需要数据库
- 方便和其他系统交互

**缺点：**
- 大文件读写慢
- 不支持查询
- 不适合增量写入

**适用场景：**
- 配置文件
- 小量非结构化数据
- API响应缓存

### 第三步：MySQL（关系型数据库）

**特点：**
- 最流行的关系型数据库
- 支持SQL查询
- 支持事务
- 数据结构需要预先定义

**优点：**
- 查询功能强大
- 支持复杂关联查询
- 数据一致性好
- 生态成熟，工具多

**缺点：**
- 需要安装和维护
- 表结构需要预先设计
- 非结构化数据支持差
- 写入性能一般

**适用场景：**
- 结构化数据
- 需要复杂查询
- 数据量中等（百万级）
- 需要事务保证

**代码示例：**
```python
import pymysql

# 连接数据库
conn = pymysql.connect(
    host='localhost',
    user='root',
    password='password',
    db='spider',
    charset='utf8mb4'
)
cursor = conn.cursor()

# 创建表
cursor.execute("""
    CREATE TABLE IF NOT EXISTS products (
        id INT AUTO_INCREMENT PRIMARY KEY,
        title VARCHAR(500),
        price DECIMAL(10,2),
        url VARCHAR(1000),
        crawl_time DATETIME
    )
""")

# 插入数据
sql = "INSERT INTO products (title, price, url) VALUES (%s, %s, %s)"
cursor.execute(sql, ('商品1', 99.00, 'https://...'))
conn.commit()

# 查询
cursor.execute("SELECT * FROM products WHERE price > 50")
results = cursor.fetchall()
```

### 第四步：MongoDB（文档型数据库）

**特点：**
- NoSQL文档数据库
- 数据以JSON格式存储
- 不需要预定义表结构
- 支持嵌套文档

**优点：**
-  schema灵活，适合爬虫数据
- 写入性能好
- 支持复杂查询
- 水平扩展容易

**缺点：**
- 占用空间大
- 事务支持弱（4.0后支持多文档事务）
- 关联查询差
- 需要学习MongoDB查询语法

**适用场景：**
- 非结构化/半结构化数据
- 数据结构经常变化
- 大数据量（千万级）
- 高并发写入

**代码示例：**
```python
from pymongo import MongoClient

# 连接
client = MongoClient('mongodb://localhost:27017/')
db = client['spider']
collection = db['products']

# 插入
product = {
    'title': '商品1',
    'price': 99,
    'url': 'https://...',
    'tags': ['手机', '数码'],
    'specs': {'color': '黑色', 'memory': '128G'}
}
collection.insert_one(product)

# 查询
results = collection.find({'price': {'$gt': 50}})
for r in results:
    print(r['title'])

# 更新
collection.update_one({'title': '商品1'}, {'$set': {'price': 89}})
```

### 第五步：Redis（缓存/队列）

**特点：**
- 内存数据库，速度极快
- 支持多种数据结构
- 持久化可选
- 适合做缓存和队列

**优点：**
- 速度极快（内存操作）
- 支持字符串、列表、集合、哈希等
- 适合做URL去重、任务队列
- 发布订阅功能

**缺点：**
- 内存有限，不适合存大量数据
- 数据可能丢失（没开持久化）
- 查询功能弱

**适用场景：**
- URL去重（集合）
- 任务队列（列表）
- 缓存（字符串）
- 分布式爬虫调度

**代码示例：**
```python
import redis

r = redis.Redis(host='localhost', port=6379, db=0)

# URL去重
r.sadd('urls', 'https://example.com/1')
if r.sismember('urls', 'https://example.com/1'):
    print("已爬过")

# 任务队列
r.lpush('queue', 'https://example.com/1')
url = r.rpop('queue')

# 缓存
r.set('cache:page1', '<html>...</html>', ex=3600)
```

### 第六步：其他存储

**1. SQLite**
- 轻量级关系型数据库
- 单文件，不需要服务
- 适合小型项目和嵌入式
- Python内置支持

**2. PostgreSQL**
- 功能强大的关系型数据库
- 支持JSON、全文搜索
- 适合复杂查询和分析

**3. Elasticsearch**
- 全文搜索引擎
- 适合需要搜索的场景
- 可以和MySQL/MongoDB配合

**4. HBase / HDFS**
- 大数据存储
- 适合亿级以上数据
- 需要Hadoop生态

### 第七步：选择建议

| 数据量 | 推荐存储 |
|--------|---------|
| <1万条 | CSV/Excel |
| 1万-10万条 | CSV/Excel/SQLite |
| 10万-100万条 | MySQL/SQLite |
| 100万-1000万条 | MySQL/MongoDB |
| 1000万条以上 | MongoDB/分布式数据库 |

| 场景 | 推荐存储 |
|------|---------|
| 交付给客户 | CSV/Excel |
| 结构化数据，需要查询 | MySQL |
| 非结构化数据，结构多变 | MongoDB |
| URL去重/任务队列 | Redis |
| 小型项目，不想装数据库 | SQLite/CSV |
| 全文搜索 | Elasticsearch |
| 分布式爬虫调度 | Redis |

**组合使用：**
- MySQL存主数据 + Redis做缓存和去重
- MongoDB存原始数据 + Elasticsearch做搜索
- CSV做交付 + MySQL做长期存储

## 完整代码

```python
# 统一的数据存储接口
import csv
import json
from abc import ABC, abstractmethod

class BaseStorage(ABC):
    @abstractmethod
    def save(self, item):
        pass
    
    @abstractmethod
    def save_batch(self, items):
        pass

class CsvStorage(BaseStorage):
    def __init__(self, filename, fields):
        self.filename = filename
        self.fields = fields
        self.file = open(filename, 'w', newline='', encoding='utf-8')
        self.writer = csv.DictWriter(self.file, fieldnames=fields)
        self.writer.writeheader()
    
    def save(self, item):
        self.writer.writerow({k: item.get(k, '') for k in self.fields})
    
    def save_batch(self, items):
        for item in items:
            self.save(item)
    
    def close(self):
        self.file.close()

class JsonStorage(BaseStorage):
    def __init__(self, filename):
        self.filename = filename
        self.data = []
    
    def save(self, item):
        self.data.append(item)
    
    def save_batch(self, items):
        self.data.extend(items)
    
    def close(self):
        with open(self.filename, 'w', encoding='utf-8') as f:
            json.dump(self.data, f, ensure_ascii=False, indent=2)

class MysqlStorage(BaseStorage):
    def __init__(self, host, user, password, db, table):
        import pymysql
        self.conn = pymysql.connect(host=host, user=user, password=password, db=db, charset='utf8mb4')
        self.cursor = self.conn.cursor()
        self.table = table
    
    def save(self, item):
        keys = ', '.join(item.keys())
        values = ', '.join(['%s'] * len(item))
        sql = f"INSERT INTO {self.table} ({keys}) VALUES ({values})"
        self.cursor.execute(sql, list(item.values()))
        self.conn.commit()
    
    def save_batch(self, items):
        for item in items:
            self.save(item)
    
    def close(self):
        self.cursor.close()
        self.conn.close()

# 使用
storage = CsvStorage('data.csv', ['title', 'price', 'url'])
storage.save({'title': '商品1', 'price': 99, 'url': 'https://...'})
storage.close()
```

## 注意事项

1. **编码问题** — CSV和文件存储注意用utf-8编码，避免乱码
2. **数据去重** — 存储前最好去重，MySQL用唯一索引，MongoDB用唯一索引
3. **增量写入** — 大量数据不要一条一条写，用批量写入提高性能
4. **备份** — 重要数据要定期备份
5. **数据安全** — 包含个人信息的数据要加密存储，注意合规
