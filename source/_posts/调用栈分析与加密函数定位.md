## 适用场景

XHR断点后断在库代码里，不知道业务代码在哪里。需要学会分析调用栈，从底层的请求函数向上追溯，找到加密参数的业务代码。

## 实现原理

调用栈（Call Stack）记录了函数的调用链。当代码在某个位置暂停时，Call Stack面板会显示从当前函数到最外层的所有调用帧。通过点击不同的帧，可以查看每个函数的参数、局部变量和代码，从而追溯参数是在哪里被处理和加密的。

## 具体步骤

### 第一步：理解调用栈

调用栈的显示顺序：
- **最上面**：当前执行的函数（最内层）
- **往下**：调用当前函数的函数
- **最下面**：最外层的入口函数

例如：
```
send (xhr.js:12)          ← 当前在这里（库代码）
ajax (jquery.js:100)     ← jquery调用了send
request (api.js:50)      ← 业务代码调用了ajax
fetchData (main.js:200)  ← 业务代码调用了request
 onclick (index.html:10) ← 点击事件触发
```

分析时从下往上看，找到业务代码的位置。

### 第二步：XHR断点后分析

1. 设置XHR断点，触发请求
2. 断住后，当前一般在`XMLHttpRequest.send`或`fetch`
3. 查看Call Stack，从下往上找
4. 跳过库代码（jquery、axios等）
5. 找到第一个业务代码的帧
6. 点击进入，查看参数是怎么处理的

**技巧：**
- 库代码的文件名一般是`jquery.min.js`、`axios.min.js`等
- 业务代码的文件名一般是项目相关的，如`app.js`、`main.js`
- 黑盒库代码后，单步会直接跳到业务代码

### 第三步：在调用栈中查看变量

点击任意一帧，可以查看：
- **Scope**：该函数的局部变量、参数
- **代码**：该函数的源代码
- **闭包变量**：函数引用的外部变量

**操作：**
1. 点击Call Stack中的某一帧
2. 代码面板跳转到对应位置
3. Scope面板显示该帧的变量
4. 可以在Console中输入变量名查看

### 第四步：向上追溯加密逻辑

典型的追溯过程：

1. **断在send处**：查看请求的URL和参数，发现sign是加密的
2. **上一帧**：可能是ajax封装函数，参数已经组装好了
3. **再上一帧**：业务函数，在这里组装参数，调用了加密函数
4. **进入加密函数**：找到sign的生成逻辑
5. **分析加密算法**：单步跟踪，看用了什么加密

### 第五步：Restart Frame（重新执行）

Chrome支持重新执行某个函数帧：

1. 在Call Stack中右键某一帧
2. 选择"Restart frame"
3. 会重新执行该函数
4. 可以在函数入口处打断点，重新跟踪

**适用场景：**
- 错过了关键代码，想重新看
- 想在函数入口处打断点
- 想多次观察变量变化

### 第六步：Async调用栈

异步代码（Promise、setTimeout）的调用栈默认不显示完整链路：

1. 开启Async栈：Call Stack面板 → 勾选"Async"
2. 可以看到异步操作的完整调用链
3. 适合分析Promise、async/await的代码

### 第七步：实战案例

**场景：** 登录接口的password是加密的，找加密函数

1. 设置XHR断点，关键词`login`
2. 点击登录按钮，断住
3. Call Stack显示：
   ```
   send (xhr)
   ajax (jquery)
   login (login.js:30)    ← 业务代码
   onclick (index.html)
   ```
4. 点击`login`帧，进入login.js第30行
5. 看到代码：
   ```javascript
   function login(username, password) {
       var encryptedPassword = encrypt(password);  ← 加密函数
       $.ajax({
           url: '/api/login',
           data: {username: username, password: encryptedPassword}
       });
   }
   ```
6. 在`encrypt(password)`处打断点
7. 重新登录，断住后Step into进入encrypt函数
8. 分析加密算法

## 完整代码

```javascript
// 调用栈分析辅助脚本，在Console中运行

// 1. 打印当前调用栈
function printStackTrace() {
    const stack = new Error().stack;
    console.log('当前调用栈:');
    console.log(stack);
    return stack;
}

// 2. Hook函数并打印调用栈
function hookWithStackTrace(obj, funcName) {
    const orig = obj[funcName];
    obj[funcName] = function(...args) {
        console.log(`=== 调用 ${funcName} ===`);
        console.log('参数:', args);
        console.log('调用栈:');
        console.log(new Error().stack);
        const result = orig.apply(this, args);
        console.log('返回:', result);
        console.log('==================');
        return result;
    };
}

// 3. 监控对象的所有方法调用
function monitorObject(obj, objName) {
    for (const key in obj) {
        if (typeof obj[key] === 'function') {
            const orig = obj[key];
            obj[key] = function(...args) {
                console.log(`[${objName}.${key}]`, args);
                return orig.apply(this, args);
            };
        }
    }
}

// 使用示例
// hookWithStackTrace(JSON, 'stringify');
// monitorObject(window, 'window');
```

## 注意事项

1. **从下往上找** — Call Stack最上面是当前函数，业务代码一般在下面
2. **跳过库代码** — jquery、axios等库代码不用看，直接找业务代码
3. **黑盒库** — 把库加入黑盒，单步会自动跳过
4. **Restart Frame** — 错过了可以重新执行，不用重新触发请求
5. **Async栈** — 异步代码要开启Async选项，不然调用栈不完整
